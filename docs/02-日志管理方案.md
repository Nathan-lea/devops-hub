# 日志管理方案

## 一、方案选型对比

| 方案 | 日志量级 | 资源占用 | 查询能力 | 推荐度 |
|------|----------|----------|----------|--------|
| **Loki + Promtail** | 中小（<500GB/日） | 低 | LogQL，适合运维 | ⭐⭐⭐⭐⭐ |
| ELK (Elasticsearch) | 大（>500GB/日） | 高 | 全文检索强 | ⭐⭐⭐⭐ |
| ClickHouse + Vector | 超大 | 中 | SQL 查询 | ⭐⭐⭐ |

> 100 台主机 + 中间件日志，日均 < 100GB，**推荐 Loki + Promtail**，与 Grafana 体系无缝整合。

## 二、架构设计

```

│              Grafana 日志查询                  │

                    │
┌───────────────────▼───────────────────────────┐
│                Loki 存储                       │

                    │ HTTP Push
┌───────────────────▼───────────────────────────┐
│              Promtail 采集端                   │
│  tail 日志文件 -> 解析标签 -> 推送 Loki         │
└───────────────────┬───────────────────────────┘
                    │
   ┌────────────────┼────────────────┐
   ▼                ▼                 ▼
/var/log/        mysql慢日志        k8s容器日志
secure/messages  nginx access       /var/log/containers
```

## 三、日志分类与采集策略

### 3.1 日志分类与保留策略
| 日志类型 | 采集源 | 标签 | 保留 | 示例 |
|----------|--------|------|------|------|
| 系统日志 | /var/log/messages, secure | job=syslog | 30 天 | SSH 登录、sudo |
| MySQL 慢日志 | slow.log | job=mysql_slow | 90 天 | 慢 SQL 分析 |
| MySQL 错误日志 | error.log | job=mysql_err | 90 天 | 死锁、OOM |
| Nginx access | access.log | job=nginx_access | 15 天 | 访问统计 |
| Nginx error | error.log | job=nginx_error | 30 天 | 5xx 分析 |
| K8s 容器 | /var/log/containers | job=k8s | 15 天 | 应用日志 |
| 应用日志 | /app/logs/*.log | job=app | 30 天 | 业务日志 |
| 审计日志 | /var/log/audit | job=audit | 180 天 | 合规要求 |

### 3.2 Promtail 采集配置

详见 `configs/promtail.yml`。

### 3.3 采集优化要点
1. **标签精简**：只保留 `host`、`job`、`app` 等高基数标签，避免把 request_id 当标签
2. **多阶段解析**：用 pipeline_stages 把日志解析为结构化字段
3. **采样与限流**：高 QPS 日志配置 rate_limit
4. **压缩传输**：默认 gzip 压缩，降低带宽
5. **本地缓存**：Promtail 本地缓存 10MB，断网不丢日志

## 四、日志查询规范（LogQL）

### 4.1 常用查询示例
```logql
# 1. 查某台主机的所有错误日志
{host="web-01", job="syslog"} |= "error"

# 2. 统计最近 1 小时各主机 SSH 登录失败次数
sum by (host) (
  count_over_time({job="syslog"} |= "Failed password" [1h])
)

# 3. 查询 MySQL 慢查询日志（耗时>1s）
{job="mysql_slow"} | regexp "Query_time: (?P<qt>[0-9.]+)" | qt > 1

# 4. K8s 某命名空间错误日志
{k8s_namespace_name="prod", job="k8s"} |= "error" | json

# 5. Nginx 5xx 错误统计
sum by (host) (
  count_over_time({job="nginx_access"} | regexp "HTTP/[0-9.]+\" (?P<status>5[0-9]{2})" [5m])
)
```

### 4.2 告警集成
日志告警通过 Loki Ruler 配置，推送到 Alertmanager：
```yaml
# 告警示例：SSH 爆破检测
- name: ssh_brute_force
  rules:
  - alert: SshBruteForceDetected
    expr: sum by (host) (count_over_time({job="syslog"} |= "Failed password" [5m])) > 20
    for: 1m
    labels:
      severity: critical
    annotations:
      summary: "{{ $labels.host }} 疑似 SSH 爆破"
```

## 五、存储与保留策略

### 5.1 Loki 存储配置
| 项 | 单节点 | 分布式 |
|----|--------|--------|
| 索引 | BoltDB (本地) | BoltDB Shipper + 对象存储 |
| 数据块(Chunks) | 本地文件系统 | S3/MinIO |
| 推荐规格 | 4C8G + 500G | 8C16G×3 + 对象存储 |
| 日均量 | ~10GB | - |
| 保留 | 30 天 | 90+ 天 |

### 5.2 存储估算
- 100 台主机日均日志 ~50GB（压缩前）
- Loki 压缩比 ~10x，实际存储 ~5GB/日
- 30 天保留 → ~150GB
- 建议 **500G SSD** 预留余量
