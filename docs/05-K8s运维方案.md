# Kubernetes 运维方案

## 一、集群架构建议

### 1.1 推荐拓扑（生产可用）
```
                        ┌─────────────┐
   外部流量 ───────────->│  Ingress    │  (nginx-ingress / traefik)
                        │  Controller │
                        └──────┬──────┘
                               │
          ┌────────────────────┼────────────────────┐
          ▼                    ▼                    ▼
   ┌──────────────┐   ┌──────────────┐   ┌──────────────┐
   │  Master-1    │   │  Master-2    │   │  Master-3    │  (控制面 3节点)
   │ etcd/apiserver│  │ etcd/apiserver│  │ etcd/apiserver│
   └──────────────┘   └──────────────┘   └──────────────┘
          │                    │                    │
   ┌──────┴──────┐    ┌────────┴──────┐    ┌────────┴──────┐
   │ Worker-1    │    │ Worker-2      │    │ Worker-3     │  (工作节点 N台)
   │ kubelet     │    │ kubelet       │    │ kubelet      │
   │ kube-proxy  │    │ kube-proxy    │    │ kube-proxy   │
   └─────────────┘    └──────────────┘    └──────────────┘
```

- **控制面**：3 节点（高可用），etcd 堆叠或外部
- **工作节点**：按业务量 3~N 台
- **LB**：控制面前置 HAProxy + Keepalived（VIP）
- **Ingress**：Nginx-Ingress 或 Traefik

### 1.2 版本选择
| 组件 | 推荐版本 | 说明 |
|------|----------|------|
| Kubernetes | v1.28~1.30 LTS | 选取社区活跃版本 |
| 容器运行时 | containerd 1.7 | Docker 已废弃 |
| CNI | Calico / Cilium | Calico 稳定，Cilium 性能优 |
| CSI | 按云厂商选择 | 云盘/文件存储 |
| Ingress | nginx-ingress | 生态最广 |

## 二、集群部署与维护

### 2.1 部署方式选型
| 方式 | 适用场景 | 推荐度 |
|------|----------|--------|
| **kubeadm** | 自建/裸机/私有云 | ⭐⭐⭐⭐⭐ |
| RKE2 | 私有云、合规要求 | ⭐⭐⭐⭐ |
| 云厂商托管 ACK/TKS | 公有云 | ⭐⭐⭐⭐⭐ |
| Kubespray(Ansible) | 大规模自建 | ⭐⭐⭐⭐ |

> 自建推荐 kubeadm + Ansible 封装；公有云优先用托管服务。

### 2.2 关键配置
- **etcd 备份**：每日快照，保留 7 天（详见备份章节）
- **证书有效期**：默认 1 年，升级到 10 年或定期轮换
- **Pod CIDR**：10.244.0.0/16
- **Service CIDR**：10.96.0.0/12
- **kubelet**：--max-pods=110, --pod-pids-limit=4096

### 2.3 集群升级流程（重要）
```bash
# 升级前检查
kubeadm upgrade plan
kubectl get nodes -o wide

# 1. 先升级控制面（逐台）
kubeadm upgrade apply v1.30.0
# 在每个 master 上执行
apt-get upgrade -y kubeadm kubelet kubectl
systemctl restart kubelet

# 2. 再升级工作节点（逐台，先驱逐）
kubectl drain <node> --ignore-daemonsets --delete-emptydir-data
kubeadm upgrade node
apt-get upgrade -y kubelet kubectl
systemctl restart kubelet
kubectl uncordon <node>

# 3. 验证
kubectl get nodes
kubectl get pods -A
```

**升级原则**：
- 一次只能跨 1 个小版本（1.28->1.29->1.30）
- 升级前必须备份 etcd
- 业务低峰期操作
- 先升级非生产集群验证

## 三、监控与可观测性

### 3.1 监控组件栈
```
┌─────────────────────────────────────┐
│  Grafana 展示                       │
└───────────────┬─────────────────────┘
                │
┌───────────────▼─────────────────────┐
│  Prometheus + kube-prometheus-stack │
│  (含 node-exporter, kube-state-metrics)│
└───────────────┬─────────────────────┘
                │
   ┌────────────┼────────────┐
   ▼            ▼            ▼
cAdvisor    metrics-server  kube-state
(容器资源)   (HPA 调度)      (对象状态)
```

### 3.2 关键监控指标
| 层级 | 指标 | 告警阈值 |
|------|------|----------|
| Node | CPU > 80% | 持续 5m |
| Node | 内存 > 85% | 持续 5m |
| Node | 磁盘 > 85% | 持续 5m |
| Node | 磁盘 inode > 80% | 持续 5m |
| Pod | Pending > 5m | Major |
| Pod | CrashLoopBackOff | Critical |
| Pod | 重启次数 > 5/5m | Major |
| Deployment | 可用副本 < 期望 | Critical |
| etcd | leader 丢失 | Critical |
| etcd | fsync 延迟 > 100ms | Major |
| API Server | 5xx 错误率 > 1% | Major |
| API Server | P99 延迟 > 1s | Major |

### 3.3 事件监控
部署 `kubernetes-event-exporter`，将 K8s Event 推送到 Loki/钉钉：
```yaml
# 关键事件告警
- Warning: FailedScheduling, Unhealthy, BackOff
- Normal: NodeNotReady, NodeReady (状态变化)
```

## 四、日常运维操作

### 4.1 节点维护
```bash
# 节点排空（维护前）
kubectl drain k8s-w1 --ignore-daemonsets --delete-emptydir-data --force

# 维护完成后恢复
kubectl uncordon k8s-w1

# 查看节点资源
kubectl describe node k8s-w1
kubectl top nodes
```

### 4.2 故障排查三板斧
```bash
# 1. Pod 异常
kubectl describe pod <pod> -n <ns>     # 看事件
kubectl logs <pod> -n <ns> --previous  # 看上次崩溃日志
kubectl get events -n <ns> --sort-by=.lastTimestamp

# 2. 节点异常
kubectl describe node <node>
journalctl -u kubelet --since "1 hour ago"
systemctl status kubelet containerd

# 3. 网络异常
kubectl get svc -A                    # 服务发现
kubectl get endpoints -A              # 端点
kubectl exec -it <pod> -- curl <svc>  # 内部访问
```

### 4.3 资源配额管理
```yaml
# namespace 资源配额
apiVersion: v1
kind: ResourceQuota
metadata:
  name: prod-quota
  namespace: prod
spec:
  hard:
    requests.cpu: "50"
    requests.memory: 100Gi
    limits.cpu: "80"
    limits.memory: 150Gi
    persistentvolumeclaims: "20"
    count/deployments: "10"
```

### 4.4 镜像与仓库
- 搭建私有镜像仓库（Harbor）
- 镜像漏洞扫描（Trivy 集成 Harbor）
- 镜像签名（Cosign）
- 拉取凭证：imagePullSecrets

## 五、安全加固

### 5.1 集群基线（kube-bench）
```bash
# 运行 CIS 基线检查
kube-bench run --targets=node
kube-bench run --targets=master
```

### 5.2 RBAC 最小权限
- 禁止使用 default ServiceAccount
- 按命名空间分配角色
- 定期审计 ClusterRoleBinding
- 禁止 cluster-admin 滥用

### 5.3 网络策略
```yaml
# 默认拒绝所有入站
apiVersion: networking.k8s.io/v1
kind: NetworkPolicy
metadata:
  name: default-deny
  namespace: prod
spec:
  podSelector: {}
  policyTypes: [Ingress]
```

### 5.4 Pod 安全标准
- 启用 Pod Security Admission（PSA）
- 生产命名空间强制 restricted 级别
- 禁止 privileged / hostNetwork / hostPath
