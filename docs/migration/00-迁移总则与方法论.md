# 迁移总则与方法论

> **所有迁移操作必读**。本文定义迁移的风险分级、阶段模型、铁律与回滚原则，
> 各迁移类型 SOP 文档均基于此方法论编制。

---

## 一、迁移风险等级定义

| 等级 | 定义 | 典型场景 | 审批要求 | 停机窗口 |
|------|------|----------|----------|----------|
| P0 | 核心业务库迁移、生产集群跨云 | MySQL->TiDB、K8s 跨云 | CTO + SRE Leader + 业务方 | 需停机窗口 |
| P1 | 非核心库迁移、Web 服务器迁移 | PG->TiDB、Nginx 迁移 | SRE Leader + 业务方 | 低峰窗口 |
| P2 | 同构扩容迁移、测试环境迁移 | 从库迁移、Staging 迁移 | SRE 值班 | 随时 |

## 二、迁移六大阶段模型

```
┌──────────┐   ┌──────────┐   ┌──────────┐   ┌──────────┐   ┌──────────┐   ┌──────────┐
│ ① 评估   │──>│ ② 准备   │──>│ ③ 预迁移 │──>│ ④ 切换   │──>│ ⑤ 验证   │──>│ ⑥ 清理   │
│ 评估     │   │ 环境/工具 │   │ 全量+增量 │   │ 流量切换 │   │ 一致性校验│   │ 下线源端 │
│ 兼容性   │   │ 备份/回滚 │   │ 数据同步  │   │ DNS/路由 │   │ 业务验证  │   │ 资源回收 │
└──────────┘   └──────────┘   └──────────┘   └──────────┘   └──────────┘   └──────────┘
```

| 阶段 | 关键产出 | 退出条件 |
|------|----------|----------|
| ① 评估 | 兼容性报告、数据量盘点、影响面分析、迁移方案选型 | 评估报告通过评审 |
| ② 准备 | 目标环境就绪、网络打通、备份完成、回滚预案就绪、脚本通过测试 | `pre_migration_check.sh` 全绿 |
| ③ 预迁移 | 全量数据同步完成 + 增量同步追平 | 数据一致性校验通过 |
| ④ 切换 | 流量灰度切换、双写/双读验证 | 业务流量全部切至目标端 |
| ⑤ 验证 | 功能验证 + 性能验证 + 数据校验 | `migration_data_verify.sh` 全绿 |
| ⑥ 清理 | 源端下线、资源回收、文档更新 | 观察 7 天无异常后下线源端 |

## 三、迁移七大铁律

1. **备份先行**--迁移前必须完成一次完整备份，并验证可恢复
2. **可回滚**--每个阶段必须有明确的回滚路径，切换前设置回滚点
3. **灰度切换**--禁止一次性全量切换，按 10%->50%->100% 灰度
4. **数据校验**--切换前后均需校验数据一致性，禁止"感觉对了"就切
5. **增量追平**--全量迁移后必须增量同步追平，延迟 < 1s 方可切换
6. **双人在场**--P0/P1 级迁移全程双人在场，一人操作一人复核
7. **窗口锁定**--迁移窗口内禁止其他变更，减少干扰变量

## 四、回滚通用原则

```
切换前回滚：直接停增量同步，源端继续提供服务（零影响）
切换中回滚：DNS/路由切回源端，目标端停止写入（<5min 恢复）
切换后回滚：需反向同步增量数据（耗时，需评估是否值得回滚）
```

> **关键**：切换后回滚代价最高。务必在切换前充分验证，确保切换后无需回滚。
> 详细的回滚操作见各 SOP 文档的"回滚步骤"章节，辅助脚本见
> `scripts/migration/migration_rollback.sh`。

## 五、灰度切换通用模型

所有迁移类型的流量切换均遵循以下灰度模型：

```
权重 100/0  ──>  90/10  ──>  50/50  ──>  10/90  ──>  0/100
  源/目            源/目       源/目       源/目       源/目
   │                │           │           │           │
   │   观察30min    │ 观察30min │ 观察1h    │ 观察2h    │
   │   错误率=0     │ 错误率=0  │ 错误率=0  │ 错误率=0  │
   └───────────────────────────────────────────────────┘
                        全量切换完成
```

| 切换机制 | 实现方式 | 适用场景 |
|----------|----------|----------|
| DNS 加权 | Route53/阿里云 DNS 加权路由 | 跨云迁移、Web 迁移 |
| 负载均衡 | LB 后端池灰度增删 | 同云内迁移 |
| 配置中心 | 应用数据源配置灰度（10%->100%） | DB 迁移 |
| Ingress Canary | Nginx Ingress canary-weight | K8s 迁移 |
| Service Mesh | Istio VirtualService 权重路由 | K8s 微服务迁移 |

## 六、各 SOP 文档统一结构

每个迁移类型 SOP 文档均包含以下标准章节，确保操作一致性：

| 章节 | 内容 | 作用 |
|------|------|------|
| 一、适用场景与前置条件 | 何时用、需要什么 | 快速判断是否适用 |
| 二、角色与职责分工 | 谁做什么 | 明确分工，避免遗漏 |
| 三、操作步骤 | 编号化步骤 + 每步验证点 | 逐步执行，逐步确认 |
| 四、检查清单 | 打勾式 | 执行前/后逐项确认 |
| 五、回滚步骤 | 编号化回滚操作 | 快速回滚 |
| 六、异常处理 | 常见异常与处置 | 应急参考 |
| 七、操作记录模板 | 填写式表格 | 留档追溯 |
