# 数据库跨云迁移标准 SOP

> **风险等级**：P0/P1 | **预计窗口**：4-12 小时（视数据量） | **停机**：可灰度免停机
> 适用：MySQL/PG/TiDB 在私有云与公有云之间迁移

---

## 一、适用场景与前置条件

### 1.1 迁移场景

| 场景 | 源端 | 目标端 | 特点 |
|------|------|--------|------|
| 私有云 -> 公有云 | 自建 DB | 云托管 RDS | 降运维成本、弹性伸缩 |
| 公有云 -> 私有云 | 云托管 RDS | 自建 DB | 数据主权、成本优化 |
| 公有云 A -> 公有云 B | 云A RDS | 云B RDS | 多云容灾、避免锁定 |

### 1.2 网络打通方案（前置条件）

| 方案 | 带宽 | 延迟 | 成本 | 适用场景 |
|------|------|------|------|----------|
| 专线/Direct Connect | 高 | <2ms | 高 | 大数据量生产迁移 |
| IPsec VPN | 中 | 5-20ms | 低 | 中小数据量 |
| 云对等连接 (VPC Peering) | 高 | <1ms | 低 | 同云厂商跨区域 |
| 公网 + TLS | 低 | 不稳定 | 低 | 仅紧急/小数据量 |

### 1.3 前置条件
- [ ] 网络已打通（专线/VPN/对等连接），延迟 < 5ms
- [ ] 安全组/防火墙已放行源端 -> 目标端数据库端口
- [ ] 目标云数据库实例已创建，参数已调优
- [ ] DNS TTL 已提前 24h 调至 60s
- [ ] 迁移前完整备份已验证可恢复

## 三、操作步骤

### 步骤 1：迁移前环境检查

```bash
bash scripts/migration/pre_migration_check.sh \
  --source <私有云DB-IP> --target <公有云DB-IP> --type db
```

```bash
# 网络质量验证（迁移前必须）
ping -c 100 <目标端内网IP>         # 丢包率 < 0.1%
iperf3 -c <目标端IP>               # 带宽满足迁移窗口需求
nc -zv <目标端IP> 3306             # 数据库端口可达
```
- **验证**：网络连通、端口可达、带宽充足

### 步骤 2：部署同步工具

```
方案 A（自建工具）：私有云 MySQL ──DM──> 公有云自建 TiDB/MySQL
方案 B（云厂商工具）：私有云 MySQL ──DTS──> 公有云 RDS
方案 C（混合）：私有云 MySQL ──DM──> 公有云中转 ──DTS──> 公有云 RDS
```

**以方案 A（DM）为例**（详细步骤见 `01-MySQL迁移至TiDB-SOP.md` 步骤 2-5）：
```bash
# 部署 DM-Worker 在私有云侧
# 配置 source 指向私有云 MySQL，target 指向公有云 DB
# 启动全量+增量同步
```
- **验证**：DM 任务 Running，增量同步延迟 < 1s

### 步骤 3：数据校验

```bash
bash scripts/migration/migration_data_verify.sh \
  --source <私有云DB-IP> --target <公有云DB-IP> \
  --type mysql --db app_db
```
- **验证**：行数一致，校验和一致

### 步骤 4：DNS/配置中心灰度切换

```bash
# 原: jdbc:mysql://10.0.2.10:3306/app_db       （私有云）
# 新: jdbc:mysql://<公有云RDS地址>:3306/app_db  （公有云）

# 灰度：10% -> 50% -> 100%（见 00-迁移总则与方法论 灰度模型）
```
- **验证**：各灰度阶段错误率 = 0

### 步骤 5：TiDB 跨云迁移（特殊场景）

```bash
# TiDB 跨云推荐 BR 备份恢复 + CDC 增量
# 5.1 全量：BR 备份到对象存储 -> 目标云 BR 恢复
br backup full --pd "10.0.4.10:2379" -u "s3://db-backup/tidb-full/"
br restore full --pd "<公有云PD>:2379" -u "s3://db-backup/tidb-full/"

# 5.2 增量：TiDB CDC 同步
tiup cdc cli changefeed create \
  --pd "10.0.4.10:2379" \
  --sink-uri "mysql://root:${vault_tidb_root}@<公有云TiDB>:4000/" \
  --changefeed-id "cross-cloud-cdc"
```
- **验证**：CDC changefeed 状态为 normal，延迟 < 1s

### 步骤 6：观察与源端下线
- 切换后观察 7 天，确认无异常后下线源端

## 四、检查清单

### 4.1 迁移前
- [ ] 网络已打通（专线/VPN），延迟 < 5ms，丢包 < 0.1%
- [ ] 安全组已放行数据库端口
- [ ] 目标云 DB 实例已创建，参数已调优
- [ ] DNS TTL 已调至 60s（24h 前）
- [ ] 字符集统一 utf8mb4，时区统一 Asia/Shanghai
- [ ] `pre_migration_check.sh` 全绿
- [ ] 完整备份已验证

### 4.2 切换前
- [ ] 全量+增量同步完成，延迟 < 1s
- [ ] 数据校验通过
- [ ] DNS/配置中心已准备灰度切换

### 4.3 切换后
- [ ] 100% 流量运行 2 小时无异常
- [ ] 同步工具已停止
- [ ] 观察 7 天后下线源端

## 五、回滚步骤

```
1. DNS/配置中心回切源端（<5min，DNS TTL 60s）
2. 重启增量同步工具追平数据
3. 确认应用全部回到源端
```
- **恢复时间**：< 5 分钟

> **辅助脚本**：`bash scripts/migration/migration_rollback.sh --type dns --action rollback`

## 六、异常处理

| 异常现象 | 可能原因 | 处置方法 |
|----------|----------|----------|
| 同步延迟持续增大 | 网络带宽不足、目标端写入慢 | 检查带宽；调大同步并发 |
| 跨云延迟过高 | 专线/VPN 质量问题 | 联系网络工程师排查链路 |
| 云 RDS 参数限制 | 云厂商不支持修改某些参数 | 评估参数影响，调整应用配置 |
| SSL 握手失败 | 跨公网 TLS 证书问题 | 确认 CA 证书、更新安全组 |
| DNS 切换不生效 | TTL 未生效、DNS 缓存 | 等待 TTL 过期；清理本地 DNS 缓存 |
