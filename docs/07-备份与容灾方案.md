# 备份与容灾方案

## 一、备份总原则（3-2-1 原则）
- **3** 份数据副本
- **2** 种不同介质（本地 + 对象存储）
- **1** 份异地（跨可用区/跨地域）

---

## 二、备份对象与策略矩阵

| 对象 | 备份方式 | 频率 | 保留 | 存储 | RPO | RTO |
|------|----------|------|------|------|-----|-----|
| MySQL | xtrabackup 全量 | 每日 02:00 | 7天 | 本地+S3 | 1h | 2h |
| MySQL | binlog 增量 | 实时 | 30天 | S3 | ~0 | - |
| TiDB | BR 全量 | 每日 03:00 | 7天 | S3 | 1h | 2h |
| Redis | RDB 快照 | 每日 02:00 | 7天 | 本地+S3 | 24h | 1h |
| Redis | AOF | 实时 | 7天 | 本地 | ~0 | - |
| K8s etcd | snapshot | 每日 01:00 + 变更前 | 14天 | 本地+S3 | 1h | 30m |
| K8s 资源 | Velero | 每日 04:00 | 7天 | S3 | 24h | 1h |
| 配置文件 | Git 仓库 | 实时 | 永久 | GitLab | ~0 | 5m |
| 系统日志 | Loki 归档 | 实时 | 30天 | 本地+S3 | ~0 | - |
| 监控数据 | VM 备份 | 每日 | 30天 | S3 | 24h | - |

## 三、各组件备份实施

### 3.1 MySQL 备份（xtrabackup）

#### 3.1.1 全量备份脚本
```bash
#!/bin/bash
# /usr/local/bin/mysql_full_backup.sh
BACKUP_DIR="/data/backup/mysql/$(date +%Y%m%d)"
S3_BUCKET="s3://db-backup/mysql"
RETENTION_DAYS=7

mkdir -p "$BACKUP_DIR"

# 全量备份
xtrabackup --backup --target-dir="$BACKUP_DIR" \
  --user=backup --password="$BACKUP_PASS" \
  --parallel=4 --compress

# 记录元信息
echo "backup_time=$(date -Iseconds)" > "$BACKUP_DIR/META"
echo "hostname=$(hostname)" >> "$BACKUP_DIR/META"

# 上传 S3
rclone copy "$BACKUP_DIR" "$S3_BUCKET/$(date +%Y%m%d)/" --progress

# 清理本地过期备份
find /data/backup/mysql/ -maxdepth 1 -type d -mtime +$RETENTION_DAYS -exec rm -rf {} \;

# 上传后校验
rclone check "$BACKUP_DIR" "$S3_BUCKET/$(date +%Y%m%d)/"
```

#### 3.1.2 恢复流程
```bash
# 1. 准备恢复目录
xtrabackup --prepare --target-dir=/data/backup/mysql/20260724/

# 2. 停止 MySQL
systemctl stop mysqld

# 3. 恢复数据
xtrabackup --copy-back --target-dir=/data/backup/mysql/20260724/

# 4. 修复权限
chown -R mysql:mysql /var/lib/mysql/

# 5. 启动并验证
systemctl start mysqld
mysql -e "SELECT COUNT(*) FROM business.orders;"
```

### 3.2 TiDB 备份（BR）
```bash
#!/bin/bash
# /usr/local/bin/tidb_backup.sh
DATE=$(date +%Y%m%d)
S3_PATH="s3://tidb-backup/full-$DATE"

# 全量备份
br backup full \
  --pd "10.0.4.10:2379" \
  --storage "$S3_PATH" \
  --s3.endpoint "http://minio:9000" \
  --log-file=/var/log/tidb/backup.log

# 校验
br validate restore \
  --pd "10.0.4.10:2379" \
  --storage "$S3_PATH" \
  --s3.endpoint "http://minio:9000"

# 清理 7 天前备份（通过 lifecycle 或脚本）
```

### 3.3 Redis 备份
```bash
#!/bin/bash
# /usr/local/bin/redis_backup.sh
DATE=$(date +%Y%m%d)
BACKUP_DIR="/data/backup/redis/$DATE"
S3_BUCKET="s3://db-backup/redis"

mkdir -p "$BACKUP_DIR"

# 触发 BGSAVE（非阻塞）
redis-cli -a "$REDIS_PASS" BGSAVE
# 等待完成
while [ "$(redis-cli -a "$REDIS_PASS" LASTSAVE)" = "$LASTSAVE_TIME" ]; do sleep 1; done

# 复制 RDB 和 AOF
cp /var/lib/redis/dump.rdb "$BACKUP_DIR/"
cp -r /var/lib/redis/appendonly* "$BACKUP_DIR/" 2>/dev/null

# 上传 S3
rclone copy "$BACKUP_DIR" "$S3_BUCKET/$DATE/"

# 清理过期
find /data/backup/redis/ -maxdepth 1 -type d -mtime +7 -exec rm -rf {} \;
```

### 3.4 K8s etcd 备份
```bash
#!/bin/bash
# /usr/local/bin/etcd_backup.sh
DATE=$(date +%Y%m%d-%H%M)
BACKUP_FILE="/data/backup/etcd/snapshot-$DATE.db"
S3_BUCKET="s3://k8s-backup/etcd"

# etcd 快照
ETCDCTL_API=3 etcdctl \
  --endpoints=https://127.0.0.1:2379 \
  --cacert=/etc/kubernetes/pki/etcd/ca.crt \
  --cert=/etc/kubernetes/pki/etcd/peer.crt \
  --key=/etc/kubernetes/pki/etcd/peer.key \
  snapshot save "$BACKUP_FILE"

# 上传 S3
rclone copy "$BACKUP_FILE" "$S3_BUCKET/"

# 校验快照
ETCDCTL_API=3 etcdctl snapshot status "$BACKUP_FILE"

# 清理 14 天前
find /data/backup/etcd/ -name "snapshot-*.db" -mtime +14 -delete
```

### 3.5 K8s 资源备份（Velero）
```bash
# 安装 Velero（含 S3 存储）
velero install \
  --provider aws \
  --bucket k8s-velero-backup \
  --backup-location-config region=minio,s3ForcePathStyle=true,s3Url=http://minio:9000 \
  --snapshot-location-config region=minio \
  --secret-file credentials-velero

# 每日定时备份
velero schedule create daily-backup \
  --schedule="0 4 * * *" \
  --include-namespaces prod,default \
  --ttl 168h
```

## 四、对象存储（MinIO 部署）

### 4.1 部署建议
- 独立部署 MinIO 集群（至少 4 节点，纠删码）
- 或使用公有云对象存储（OSS/S3）
- 数据至少跨 2 个可用区

### 4.2 生命周期策略
| 存储桶 | 保留 | 归档 | 删除 |
|--------|------|------|------|
| mysql-backup | 30 天热 | 30~90 天低频 | 90 天后删除 |
| tidb-backup | 30 天热 | 30~90 天低频 | 90 天后删除 |
| redis-backup | 7 天热 | - | 7 天后删除 |
| etcd-backup | 14 天热 | - | 14 天后删除 |
| k8s-velero | 7 天热 | - | 7 天后删除 |
| log-archive | 30 天热 | 30~180 天归档 | 180 天后删除 |

## 五、容灾设计

### 5.1 容灾等级
| 级别 | 描述 | RPO | RTO | 适用 |
|------|------|-----|-----|------|
| L1 | 数据备份可恢复 | 24h | 4h | 非核心 |
| L2 | 主备容灾（异机/异地） | 1h | 1h | 重要 |
| L3 | 双活/多活 | ~0 | ~0 | 核心 |

### 5.2 关键系统容灾方案
| 系统 | 容灾方案 | 切换方式 |
|------|----------|----------|
| MySQL | 主从 + 跨 AZ | MHA/Orchestrator 自动切换 |
| TiDB | 多 AZ 部署 | PD 自动调度 |
| Redis | 主从 + 哨兵跨 AZ | 哨兵自动切换 |
| K8s | 跨 AZ worker 节点 | Pod 自动重调度 |
| 监控 | Prometheus 主备 | 虚 IP / DNS 切换 |

### 5.3 DNS 与流量切换
- 使用统一的 GSLB / DNS 调度
- 健康检查驱动切换
- 回切需人工确认

## 六、恢复演练（至关重要）

### 6.1 演练计划
| 频率 | 内容 | 参与方 |
|------|------|--------|
| 每月 | 单表/单库恢复演练 | DBA + SRE |
| 每季度 | 全量恢复演练（含跨可用区） | DBA + SRE + 研发 |
| 每半年 | 完整灾备切换演练 | 全员 |

### 6.2 演练流程
```
1. 确认演练范围与时间窗口
2. 在测试环境准备恢复目标
3. 从备份恢复数据
4. 验证数据完整性（行数、校验和）
5. 应用连接验证
6. 记录 RTO/RPO 实际值
7. 复盘改进
```

### 6.3 演练记录模板
```

实际 RPO：____
```

## 七、备份监控与告警

### 7.1 监控指标
| 指标 | 告警条件 | 级别 |
|------|----------|------|
| 备份任务执行 | 未在预期时间执行 | Major |
| 备份完成时间 | > 预期 2 倍 | Minor |
| 备份大小 | 较昨日变化 > 50% | Major |
| S3 上传成功率 | < 100% | Critical |
| S3 存储用量 | > 80% | Major |
| etcd 快照 | 24h 未成功 | Critical |

### 7.2 实现方式
- 备份脚本执行后写入监控文件（node_exporter textfile）
- 或推送 metric 到 pushgateway
- Prometheus 抓取并告警
