## 二、自动化框架

### 2.1 架构
```
┌───────────────────────────────────────┐
│         任务调度（AWX/Semaphore）       │
```

## 三、核心自动化脚本

### 3.1 每日主机巡检脚本

详见 `scripts/daily_health_check.sh`，检查项：
1. 系统负载与资源使用
2. 磁盘空间（> 80% 告警）
3. 内存使用（> 90% 告警）
4. 关键进程存活（sshd/nginx/mysqld/redis）
5. 系统错误日志（dmesg, /var/log/messages）
6. 僵尸进程
7. NTP 同步状态
8. 网络连接数

### 3.2 数据库巡检脚本

详见 `scripts/db_health_check.sh`，检查项：
- MySQL：主从状态、连接数、慢查询数、表碎片率
- TiDB：PD leader、Store 状态、慢查询
- Redis：主从状态、内存、连接、持久化状态

### 3.3 K8s 巤检脚本

详见 `scripts/k8s_health_check.sh`，检查项：
- 节点状态（Ready/NotReady）
- 异常 Pod（CrashLoopBackOff/Pending）
- 资源使用率（kubectl top）
- 事件流（Warning 事件）
- 证书有效期

### 3.4 证书检查脚本
```bash
#!/bin/bash
# /usr/local/bin/cert_check.sh
# 检查域名证书有效期
DOMAINS="api.example.com www.example.com grafana.internal"
WARN_DAYS=30

for domain in $DOMAINS; do
  expiry=$(echo | openssl s_client -servername "$domain" -connect "$domain:443" 2>/dev/null \
    | openssl x509 -noout -enddate 2>/dev/null | cut -d= -f2)
  if [ -n "$expiry" ]; then
    expiry_epoch=$(date -d "$expiry" +%s)
    now_epoch=$(date +%s)
    days_left=$(( (expiry_epoch - now_epoch) / 86400 ))
    if [ "$days_left" -lt "$WARN_DAYS" ]; then
      echo "WARN: $domain 证书将在 ${days_left} 天后过期"
    fi
  fi
done
```

### 3.5 自动化日志清理
```bash
#!/bin/bash
# /usr/local/bin/log_cleanup.sh
# 清理超过 30 天的日志
find /var/log -name "*.log.*" -mtime +30 -delete
find /var/log -name "*.gz" -mtime +30 -delete
# 清理 journal（保留 7 天）
journalctl --vacuum-time=7d
# 清理 Ansible 临时文件
find /tmp/ansible_* -mtime +7 -delete 2>/dev/null
# Docker/容器日志
find /var/lib/containerd/io.containerd.snapshotter.v1.overlayfs -name "*.log" -mtime +7 -delete 2>/dev/null
```

## 四、自愈机制

### 4.1 自愈场景
| 场景 | 检测方式 | 自愈动作 |
|------|----------|----------|
| 关键进程退出 | Prometheus + node_exporter | Ansible 远程重启 |
| 磁盘空间不足 | Prometheus 告警 | 自动清理日志/tmp |
| K8s Pod Crash | kube-state-metrics | K8s 自动重启（内置） |
| MySQL 从库断开 | mysqld_exporter | 尝试自动重连 |
| 证书即将过期 | 证书检查脚本 | 自动续期 + reload |
| NTP 偏移 | chrony_exporter | 自动同步 |

### 4.2 自愈实现（Alertmanager Webhook）
```
告警 -> Alertmanager -> Webhook -> 自愈服务
                                      │
                            ┌─────────┴─────────┐
                            ▼                   ▼
                        执行自愈脚本        记录操作日志
                        (Ansible)           通知 IM
```

### 4.3 自愈安全边界
- **最多重试 3 次**，避免频繁重启造成雪崩
- **自愈失败立即升级**为人工介入
- **生产环境自愈需审批**（可配置白名单）
- **所有自愈操作记录审计**

## 六、批量操作规范

### 6.1 批量操作安全准则
1. **先小范围测试**：用 --limit 先在 1 台执行
2. **检查模式**：先 --check 预演
3. **分批执行**：用 serial 控制并发
4. **保留回滚**：变更前备份配置
5. **操作审计**：记录执行人/时间/命令

### 6.2 常用批量操作
```bash
# 批量查看磁盘
ansible all -m shell -a "df -h | grep -E '^/dev'"

# 批量检查服务状态
ansible web -m systemd -a "name=nginx state=started"

# 批量更新系统包（安全补丁）
ansible all -m yum -a "name=* state=latest security=yes" --limit "5%"

# 批量同步时间
ansible all -m shell -a "chronyc makestep"
```

## 八、安全检测自动化

### 8.1 安全检测任务矩阵
| 类别 | 任务 | 频率 | 工具 | 说明 |
|------|------|------|------|------|
| 入侵检测 | 反向Shell/rootkit/持久化后门检测 | 每 10 分钟 | intrusion_detection.sh | 5 类检测 |
| 网络异常 | 异常出站/新增端口/威胁情报匹配 | 每 5 分钟 | network_anomaly_check.sh | 8 类检测 |
| 威胁情报 | 恶意IP/域名列表更新 | 每日 03:00 | threat_intel_update.sh | 3 个情报源 |
| 暴力破解 | SSH/Nginx/MySQL/Redis 爆破防护 | 实时 | fail2ban | 自动封禁 |
| 文件完整性 | 关键配置文件变更 | 实时 | Wazuh FIM | 变更告警 |
| 容器安全 | 容器异常行为检测 | 实时 | Falco | 规则匹配 |
| 网络入侵 | 网络攻击特征匹配 | 实时 | Suricata | 规则+情报 |

### 8.2 安全检测脚本说明

#### 8.2.1 intrusion_detection.sh（入侵检测）
部署位置：`/usr/local/bin/intrusion_detection.sh`，cron 每 10 分钟执行。

| 检测项 | 检测方法 | 指标 |
|--------|----------|------|
| 反向 Shell | shell进程+socket检测、/dev/shm可执行文件、/tmp执行文件 | intrusion_detection_reverse_shell |
| Rootkit | LKM模块检测、隐藏进程对比、SUID基线对比、网卡混杂模式、ld.so.preload | intrusion_detection_rootkit |
| 异常进程 | 挖矿进程名匹配、/tmp运行的进程、已删除但运行的进程 | intrusion_detection_anomaly_process |
| 持久化后门 | 异常crontab、系统cron文件、SSH密钥数量、systemd服务、.bashrc后门 | intrusion_detection_persistence |
| 异常用户 | UID=0非root用户、空密码用户、24h新增用户、sudoers异常 | intrusion_detection_anomaly_user |

所有检测结果推送 node_exporter textfile 指标，由 Prometheus 采集，
触发 `configs/rules/security.yml` 中的告警规则。

#### 8.2.2 network_anomaly_check.sh（网络异常检测）
部署位置：`/usr/local/bin/network_anomaly_check.sh`，cron 每 5 分钟执行。

| 检测项 | 检测方法 | 指标 |
|--------|----------|------|
| 异常出站连接 | 对比白名单网段+标准端口 | network_anomaly_outbound_total |
| 新增监听端口 | 与基线对比 | network_listening_ports_new |
| 非常规端口出站 | 非标准出站端口检测 | network_nonstandard_outbound_total |
| 威胁情报匹配 | 出站IP对比恶意IP列表 | threat_intel_match_total |
| 连接数突增 | 历史平均3倍阈值 | （日志告警） |
| 横向移动 | 内网多端口连接检测 | （日志告警） |
| DNS隧道 | 异常长域名查询检测 | （日志告警） |
| 流量统计 | 网卡收发字节数 | network_interface_rx/tx_bytes |

#### 8.2.3 threat_intel_update.sh（威胁情报更新）
部署位置：`/usr/local/bin/threat_intel_update.sh`，cron 每日 03:00 执行。

| 情报源 | 内容 | 更新方式 |
|--------|------|----------|
| AbuseIPDB | 恶意IP（置信度≥90） | API 拉取 |
| AlienVault OTX | 恶意IP + 域名 | API 拉取 |
| 矿池黑名单 | 挖矿域名 | 开源列表拉取 |

更新后自动生成 Suricata 规则和 Wazuh CDB，重载服务。

### 8.3 安全自愈机制
| 场景 | 检测方式 | 自愈动作 |
|------|----------|----------|
| SSH 暴力破解 | fail2ban | 自动封禁 IP（1~24小时） |
| Web 暴力破解 | fail2ban nginx | 自动封禁 IP（1小时） |
| MySQL 爆破 | fail2ban mysqld | 自动封禁 IP（24小时） |
| Redis 爆破 | fail2ban redis | 自动封禁 IP（24小时） |
| 递归攻击 | fail2ban recidive | 长期封禁（30天） |
| Wazuh 规则触发 | Wazuh 主动响应 | firewall-drop 自动封禁 |
| 确认入侵 | 人工确认 | host_isolate.sh 隔离 + K8s cordon |

### 8.4 安全检测部署
通过 Ansible 一键部署：
```bash
# 部署 Wazuh Agent + Suricata + fail2ban扩展 + 入侵检测脚本 + 网络异常检测脚本
ansible-playbook playbooks/04-security-monitoring.yml

# 验证部署结果
ansible all -m shell -a "systemctl status wazuh-agent fail2ban"
ansible all -m shell -a "crontab -l | grep -E 'intrusion|network_anomaly'"
```
