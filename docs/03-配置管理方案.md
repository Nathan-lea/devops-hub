# 配置管理方案（Ansible）

## 一、设计目标
1. **一键纳管**：新主机上架即纳入 Ansible 清单，免手工登录
2. **配置标准化**：系统基线、内核参数、用户权限统一管理
3. **变更可追溯**：所有变更通过 Git 提交，支持回滚
4. **幂等执行**：重复执行不产生副作用

## 三、主机分组策略

### 3.1 inventory 分组（多维度）
```ini
# 按发行版
[debian]
deb-web-01 ansible_host=10.0.1.11

[ubuntu]
ubuntu-db-01 ansible_host=10.0.2.21

[centos]
centos-master-01 ansible_host=10.0.3.31

# 按角色
[mysql]
mysql-master ansible_host=10.0.2.10
mysql-slave-01 ansible_host=10.0.2.11

[tidb]
tidb-pd-01 ansible_host=10.0.4.10
tidb-tikv-01 ansible_host=10.0.4.20

[redis]
redis-master ansible_host=10.0.5.10
redis-slave-01 ansible_host=10.0.5.11

[web]
web-01 ansible_host=10.0.1.11
web-02 ansible_host=10.0.1.12

[k8s_master]
k8s-m1 ansible_host=10.0.6.10
[k8s_worker]
k8s-w1 ansible_host=10.0.6.20
k8s-w2 ansible_host=10.0.6.21

# 按环境
[prod:children]
mysql
tidb
redis
web
k8s_master
k8s_worker

[monitoring]
prometheus ansible_host=10.0.0.10
grafana ansible_host=10.0.0.11
loki ansible_host=10.0.0.12

# 按云厂商
[aliyun]
[aws]
[onprem]
```

### 3.2 分组原则
- **按发行版**：适配包管理差异（apt/yum）
- **按角色**：执行特定运维操作（如 MySQL 主从切换）
- **按环境**：生产/测试，避免误操作
- **按云厂商**：处理元数据、标签同步

## 四、关键 Playbook 说明

### 4.1 新机初始化（00-init-host.yml）
1. 创建运维用户 `ops`，配置 sudo 免密
2. 配置 SSH 公钥登录，禁用密码登录
3. 设置主机名、时区、NTP
4. 配置内网 yum/apt 镜像源
5. 安装基础工具（vim/htop/iotop/net-tools/conntrack）
6. 内核参数调优（文件句柄、网络）
7. 防火墙规则（仅放行必要端口）
8. 部署 node_exporter + Promtail
9. 注册到 CMDB

### 4.2 系统基线（01-system-baseline.yml）
- 限制定期修改密码策略（90 天）
- 禁用 root 直接 SSH
- 设置 history 记录格式（带时间戳）
- 配置 journald 持久化
- 配置 logrotate（系统日志）
- ulimit 调优
- 禁用不需要的服务（postfix/avahi）
- 定时同步时间

### 4.3 滚动重启（99-rolling-restart.yml）
- 使用 serial 关键字控制并发
- 按角色分批，先重启非核心节点
- 每批执行健康检查
- 失败即中止（any_errors_fatal）

## 五、连接与安全

### 5.1 SSH 连接管理
- 使用统一运维用户 `ops` + sudo
- 密钥集中管理，定期轮换
- Ansible Vault 加密敏感变量（密码、密钥）
- SSH 跳板：通过 ProxyJump 访问无公网主机

### 5.2 ansible.cfg 关键配置
```ini
[defaults]
inventory = inventory/hosts.ini
remote_user = ops
host_key_checking = False
roles_path = roles
gathering = smart
fact_caching = jsonfile
fact_caching_connection = /tmp/ansible_facts
forks = 20
pipelining = True
timeout = 30
retry_files_enabled = False
vault_password_file = ~/.vault_pass
```

### 5.3 敏感数据加密
```bash
# 创建加密变量文件
ansible-vault create group_vars/all/vault.yml

# 编辑
ansible-vault edit group_vars/all/vault.yml

# 执行时自动解密
ansible-playbook site.yml --ask-vault-pass
# 或使用密码文件
ansible-playbook site.yml --vault-password-file ~/.vault_pass
```

## 六、CI/CD 集成

### 6.1 GitLab CI 流程
```yaml
# .gitlab-ci.yml
stages:
  - lint
  - dry_run
  - apply

ansible_lint:
  stage: lint
  script: ansible-lint playbooks/

dry_run:
  stage: dry_run
  script: ansible-playbook playbooks/site.yml --check
  only: [merge_requests]

apply_prod:
  stage: apply
  script: ansible-playbook playbooks/site.yml
  when: manual
  only: [main]
```

### 6.2 变更审批流程
1. 工程师提交 MR -> 触发 lint + dry_run
2. 评审通过 -> 合并到 main 分支
3. 手动触发 apply_prod
4. 执行结果自动回写到 MR 评论
