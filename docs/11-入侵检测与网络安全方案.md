## 二、异常连接检测

### 2.1 异常连接类型与检测方法

| 异常类型 | 检测方法 | 工具 | 告警级别 |
|----------|----------|------|----------|
| 异常出站连接 | 对比已知白名单 IP/端口 | ss + auditd + Suricata | Critical |
| 反向 Shell | 检测非常规端口出站 + 进程关联 | auditd + 自定义脚本 | Critical |
| 端口扫描 | 短时间多端口连接 | Suricata + fail2ban | Major |
| C2 回连 | 威胁情报匹配 + DGA 域名检测 | Wazuh + 威胁情报源 | Critical |
| 隧道/代理 | DNS 隧道 + ICMP 隧道检测 | Suricata + dnsmasq 日志 | Major |
| 数据外泄 | 大流量出站 + 非常规端口 | nftables + Suricata | Critical |
| 挖矿木马 | 矿池域名/IP 连接检测 | 威胁情报 + Suricata | Critical |
| 横向移动 | 内网非常规端口扫描 | Suricata + auditd | Major |

### 2.2 异常连接检测实现

#### 2.2.1 出站连接基线管理
```bash
# 建立出站连接基线（白名单）
# 正常出站应仅包含：
#   - 应用到数据库的连接（指定端口）
#   - 监控数据上报（9100/9090等）
#   - NTP 时间同步（123/UDP）
#   - DNS 解析（53/UDP）
#   - 包管理器更新（指定镜像源）
#   - 对象存储上传（S3/MinIO端口）

# 脚本对比当前连接与基线，发现异常
# 详见 scripts/network_anomaly_check.sh
```

#### 2.2.2 进程-连接关联审计
```bash
# 通过 auditd 监控网络连接系统调用
auditctl -a always,exit -F arch=b64 -S connect -k network_connect
auditctl -a always,exit -F arch=b64 -S accept -k network_accept
auditctl -a always,exit -F arch=b64 -S bind -k network_bind

# 通过 ss -tunp 获取进程与连接的映射
# 定期快照对比，发现新出现的异常连接
```

#### 2.2.3 反向 Shell 检测
```bash
# 检测特征：
# 1. /bin/bash /bin/sh /bin/zsh 进程的网络连接
# 2. 非常规端口的出站连接（非 80/443/3306/6379 等）
# 3. 进程从 /tmp 或 /dev/shm 启动
# 4. file descriptor 指向 socket 而非 tty/pts

# 检测脚本逻辑
for pid in $(ls /proc | grep -E '^[0-9]+$'); do
  cmdline=$(cat /proc/$pid/cmdline 2>/dev/null | tr '\0' ' ')
  if echo "$cmdline" | grep -qE '(bash|sh|zsh|python|perl|nc|ncat|socat)'; then
    fd=$(ls -la /proc/$pid/fd 2>/dev/null | grep -c 'socket')
    if [ "$fd" -gt 0 ]; then
      echo "SUSPECTED_REVERSE_SHELL: pid=$pid cmd=$cmdline"
    fi
  fi
done
```

### 3.2 HIDS（主机入侵检测）

#### 3.2.1 Wazuh Agent 部署
```
┌───────────────┐         ┌───────────────────┐
│  Wazuh Server │ <────── │  Wazuh Agent(每台) │
│  (管理+分析)   │  1514   │  (日志+audit+文件) │
│               │  1515   │                    │
│  - 规则匹配    │ ──────> │  - 实时告警        │
│  - 关联分析    │         │  - 主动响应        │
│  - 威胁情报    │         │  - rootkit检测     │
└───────────────┘         └───────────────────┘
```

Wazuh 核心检测能力：
- **文件完整性监控 (FIM)**：监控关键配置文件、二进制文件变更
- **rootkit 检测**：定期扫描 rootkit 特征
- **日志分析**：系统日志、应用日志、auditd 日志关联分析
- **主动响应**：检测到攻击自动执行封禁脚本
- **CIS 基线**：自动评估安全基线合规性
- **漏洞检测**：CVE 数据库匹配已安装软件包

#### 3.2.2 Wazuh 关键规则配置
```xml
<!-- /var/ossec/etc/ossec.conf 核心配置 -->

<!-- 文件完整性监控 -->
<syscheck>
  <frequency>43200</frequency>  <!-- 12小时扫描一次 -->
  <!-- 监控关键系统文件 -->
  <directories>/etc,/usr/bin,/usr/sbin,/bin,/sbin</directories>
  <directories>/lib,/usr/lib</directories>
  <!-- 监控应用配置 -->
  <directories>/etc/nginx,/etc/mysql,/etc/redis,/etc/kubernetes</directories>
  <!-- 监控 K8s 配置 -->
  <directories>/etc/kubernetes/pki</directories>
  <!-- 监控 Web 目录 -->
  <directories realtime="yes">/var/www/html,/app</directories>
  <!-- 忽略临时文件 -->
  <ignore>/etc/mtab</ignore>
  <ignore>/etc/mnttab</ignore>
  <ignore>/var/log</ignore>
  <!-- 空白文件忽略 -->
  <nodiff>/etc/ssl/private.key</nodiff>
</syscheck>

<!-- 主动响应：自动封禁恶意 IP -->
<command>
  <name>firewall-drop</name>
  <executable>firewall-drop.sh</executable>
  <expect>srcip</expect>
  <timeout_allowed>yes</timeout_allowed>
</command>

<active-response>
  <command>firewall-drop</command>
  <location>local</location>
  <rules_id>5712,5715,5716,5717,5718</rules_id>  <!-- SSH爆破等规则 -->
  <timeout>3600</timeout>  <!-- 封禁1小时 -->
</active-response>

<!-- rootkit 检测 -->
<rootcheck>
  <rootkit_files>/var/ossec/etc/shared/rootkit_files.txt</rootkit_files>
  <rootkit_trojans>/var/ossec/etc/shared/rootkit_trojans.txt</rootkit_trojans>
  <frequency>86400</frequency>  <!-- 每日扫描 -->
</rootcheck>
```

### 3.3 NIDS（网络入侵检测）

#### 3.3.1 Suricata 部署架构
```
        ┌─────────────┐
  镜像口 │  Suricata   │ ── 告警 ──> Wazuh / Elasticsearch
        │  (IDS/IPS)  │
        └──────┬──────┘
               │
     ┌─────────┴─────────┐
     │   规则集(ET Open)  │
     │  + 自定义规则      │
     │  + 威胁情报        │
     └───────────────────┘
```

Suricata 核心能力：
- **签名检测**：基于 Emerging Threats 规则集
- **协议异常检测**：异常协议行为
- **文件提取**：传输文件哈希记录
- **流量分析**：DNS/TLS/HTTP 元数据

#### 3.3.2 Suricata 关键自定义规则
```
# SSH 暴力破解检测
alert tcp $EXTERNAL_NET any -> $HOME_NET 22222 (msg:"SSH Brute Force Attempt"; \
  flow:to_server; flags:S; threshold:type threshold, track by_src, count 5, seconds 60; \
  sid:1000001; rev:1;)

# 端口扫描检测
alert tcp $EXTERNAL_NET any -> $HOME_NET any (msg:"Port Scan - Nmap Detection"; \
  flags:S,12; detection_filter:track by_src, count 20, seconds 10; \
  sid:1000002; rev:1;)

# 反向 Shell 检测（非常规端口的出站连接）
alert tcp $HOME_NET any -> $EXTERNAL_NET ![80,443,53,123,3306,6379,9100,9090] \
  (msg:"Possible Reverse Shell - Non-standard Outbound"; \
  flow:established; dsize:>100; \
  sid:1000003; rev:1;)

# 挖矿木马连接检测（矿池域名）
alert tls $HOME_NET any -> $EXTERNAL_NET any (msg:"Cryptocurrency Mining Pool Connection"; \
  tls.subject; content:"mining"; nocase; \
  sid:1000004; rev:1;)

# DNS 隧道检测（异常长域名）
alert dns $HOME_NET any -> any any (msg:"DNS Tunneling - Long Query Name"; \
  dns.query; pcre:"/^.{50,}$/"; \
  sid:1000005; rev:1;)

# 数据外泄检测（大流量出站非常规端口）
alert tcp $HOME_NET any -> $EXTERNAL_NET ![80,443,53,123] \
  (msg:"Possible Data Exfiltration - High Volume Outbound"; \
  flow:established; threshold:type both, track by_src, count 1, seconds 60; \
  byte_test:4,>,104857600,0,relative; \
  sid:1000006; rev:1;)
```

### 4.3 Wazuh 主动响应脚本
```bash
#!/bin/bash
# /var/ossec/active-response/bin/block-ip.sh
# Wazuh 主动响应：封禁恶意 IP

ACTION=$1
USER=$2
SRCIP=$3

if [ -z "$SRCIP" ]; then
  exit 1
fi

case "$ACTION" in
  add)
    # 使用 nftables 封禁
    nft add element inet filter blacklist "{ $SRCIP }" 2>/dev/null || \
    iptables -I INPUT -s "$SRCIP" -j DROP
    logger -t ossec-active "BLOCKED IP: $SRCIP"
    ;;
  delete)
    # 解封
    nft delete element inet filter blacklist "{ $SRCIP }" 2>/dev/null || \
    iptables -D INPUT -s "$SRCIP" -j DROP
    logger -t ossec-active "UNBLOCKED IP: $SRCIP"
    ;;
esac
```

## 六、主机隔离机制

### 6.1 隔离级别
| 级别 | 触发条件 | 隔离方式 | 恢复方式 |
|------|----------|----------|----------|
| L1 网络隔离 | 疑似入侵 | 防火墙阻断所有入站（仅运维VPN） | 人工确认后解除 |
| L2 进程冻结 | 确认恶意进程 | kill 进程 + 阻断出站 | 清理后恢复 |
| L3 主机隔离 | 确认入侵/勒索 | 从负载均衡摘除 + 网络隔离 | 取证后重建 |

### 6.2 隔离脚本
```bash
#!/bin/bash
# /usr/local/bin/host_isolate.sh
# 主机隔离脚本（通过 Ansible 下发执行）

ACTION="${1:-isolate}"

if [ "$ACTION" = "isolate" ]; then
  # 阻断所有入站（仅放行运维 VPN 网段）
  iptables -I INPUT -j DROP
  iptables -I INPUT -s 10.0.0.0/8 -j ACCEPT  # 仅内网运维
  iptables -I INPUT -m state --state ESTABLISHED,RELATED -j ACCEPT

  # 从 K8s 集群摘除（如果是 worker 节点）
  if command -v kubectl >/dev/null 2>&1; then
    kubectl cordon "$(hostname)"
    kubectl drain "$(hostname)" --ignore-daemonsets --delete-emptydir-data --force --timeout=60s
  fi

  # 从负载均衡摘除
  # curl -X POST http://lb-api:8080/drain/$(hostname)

  logger -t security "HOST ISOLATED: $(hostname)"
  echo "ISOLATED"

elif [ "$ACTION" = "release" ]; then
  # 解除隔离
  iptables -D INPUT -j DROP 2>/dev/null
  if command -v kubectl >/dev/null 2>&1; then
    kubectl uncordon "$(hostname)"
  fi
  logger -t security "HOST RELEASED: $(hostname)"
  echo "RELEASED"
fi
```

#### 9.2.1 确认入侵后处理
```
1. 立即隔离（host_isolate.sh）
2. 保留证据：
   - 内存dump: dd if=/dev/mem of=/tmp/mem.dump
   - 磁盘快照: 云平台创建快照
   - 日志保全: cp /var/log/* /secure-backup/
   - 进程列表: ps auxf > /tmp/ps.txt
   - 网络连接: ss -tunap > /tmp/connections.txt
   - 定时任务: crontab -l; ls /etc/cron.*
   - SSH密钥: cat ~/.ssh/authorized_keys
3. 分析入侵路径：
   - 检查最近登录: last -50
   - 检查新增文件: find / -newer /tmp/marker -type f
   - 检查异常进程: ps auxf
   - 检查异常模块: lsmod
4. 清除威胁：
   - kill恶意进程
   - 删除后门文件/crontab/SSH密钥
   - 修改所有密码
5. 恢复：
   - 从备份重建（推荐，不信任被入侵的系统）
   - 或深度清理后恢复
6. 加固：
   - 修复入侵路径漏洞
   - 更新安全基线
7. 复盘：
   - 完整事件时间线
   - 根因分析
   - 改进措施
```

#### 9.2.2 勒索软件处理
```
1. 立即隔离主机（防止扩散）
2. 不要关机（保留内存证据）
3. 快照磁盘
4. 评估加密范围
5. 检查备份可用性
6. 从备份恢复（不支付赎金）
7. 重建主机
8. 排查入侵路径
9. 全面加固
```

#### 9.2.3 挖矿木马处理
```
1. 隔离主机网络（阻断矿池连接）
2. 定位挖矿进程: top -bn1 | grep -E '(xmrig|minerd|kdevtmpfsi)'
3. 检查持久化:
   - crontab -l
   - ls /etc/cron.d/ /var/spool/cron/
   - cat /etc/rc.local
   - systemctl list-unit-files --state=enabled
4. kill挖矿进程
5. 清除持久化项
6. 检查是否横向传播
7. 修复入侵漏洞
8. 恢复网络
```
